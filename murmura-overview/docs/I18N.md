# Languages — English and European Portuguese

The whole app (shell, overview, calendar, inbox, analytics, placeholder routes) runs in
**English** (`en`) and **European Portuguese** (`pt-PT`). English is the
reference template's own wording and stays byte-for-byte what it was before
i18n, so the pixel comparisons in [`REVERSE_ENGINEERING.md`](REVERSE_ENGINEERING.md)
still hold.

## Picking the language

1. `?lang=pt-PT` (or `?lang=en`) in the URL, e.g. `http://localhost:5173/?lang=pt-PT#/inbox`;
2. otherwise the choice saved in `localStorage` (`murmura-locale`);
3. otherwise the browser's languages: any `pt-*` (pt-PT, pt-BR, pt) → Portuguese, any `en-*` → English;
4. otherwise English.

People switch from the **account menu** (avatar, top right): *Language / Idioma*,
each language named in its own language. The choice applies instantly, is saved,
updates `<html lang>` and the document title, and drops a `?lang=` from the
URL so a reload keeps what was picked. The dock and top bar are untouched, so the
desktop layout still matches the reference.

## How it is built

```
src/i18n/
  en.tsx      English catalogue — source of truth; `Messages = typeof en`
  pt-PT.tsx   `export const ptPT: Messages = {…}` — a missing or extra key fails the build
  format.ts   cached Intl.DateTimeFormat / NumberFormat pinned to UTC, day maths
  index.tsx   I18nProvider, useI18n(), LOCALES, locale detection
```

```tsx
const { t, locale, setLocale } = useI18n()
t.inbox.markAllRead                 // plain string
t.common.post(3)                    // plurals: "3 posts" / "3 publicações"
t.dates.relativeDay(when, now)      // "Tomorrow" / "Amanhã"
t.numbers.compact(976_260)          // "976.3K" / "976,3 mil"
t.inbox.summary(<b>13</b>, <b>22m</b>)  // rich text: catalogues may return JSX around slots
```

- Catalogue entries are strings, functions (interpolation, plurals, gender
  agreement) or small JSX templates where part of a sentence is styled.
- Dates and numbers are formatted by the catalogue itself, on top of `Intl`,
  because some pt-PT CLDR defaults don't suit a UI (`month: 'short'` gives
  "30/10", `weekday: 'short'` gives "sexta").
- Data helpers no longer produce English: `selectOverview(ws, now, t)` receives
  the catalogue, `calendar.ts` returns period bounds instead of labels, and the
  activity feed and failure reasons are stored as **structured events**
  (`AuditAction`, `failure.code`) that each language turns into a sentence.

### What gets translated

| Translated (the interface speaks) | Kept as written (people wrote it) |
| --- | --- |
| labels, buttons, menus, empty states, toasts, aria-labels and tooltips | post captions, conversation messages, internal notes |
| post statuses, conversation kinds, sentiments, roles, permissions | saved replies, media titles, campaign and brand names |
| dates, times, relative times, durations, numbers, percentages | team members' job titles, tag names |
| activity feed sentences, failure reasons, the "needs you" list | |

Tags stay untranslated on purpose: they are shared identifiers, and two people
using different languages must land on the same `#support`.

## European Portuguese conventions

- 24-hour clock (`09:30`, gutter `06:00`, month chips `9:45` / `20h`), dates as
  `30 out.`, `dom., 1 nov.`, `26 out. – 1 nov. 2026`, headings `Outubro de 2026`.
- Decimal comma and pt-PT compact numbers: `10,3%`, `976,3 mil`, `8,9×`.
- Formal register (*o seu*, *Experimente*, *Arraste*), PT-PT vocabulary
  (*equipa*, *definições*, *registo*, *contacto*, *aspeto*, *faturação*).
- Roles use neutral nouns so they never assign a gender to a person:
  Owner → *Titular*, Admin → *Administração*, Manager → *Gestão*, Editor → *Edição*,
  Community → *Comunidade*.
- Toasts agree in gender with the conversation kind
  (*Feito · comentário de Abigail fechado* / *mensagem … fechada*).
- Analytics: `7 d` / `30 d` / `90 d`, millions as `10,83 M`, heatmap hours `0h … 21h`
  and slots `sáb. 08:00`, the CSV export uses `;` and decimal commas (what Excel in
  Portuguese expects) and a `murmura-analises-30d.csv` name.

Some wording was chosen to fit the template's tight spots, all checked at
1440 px and 390 px: *Mensagens* rather than *Caixa de entrada* and *Análises*
rather than *Estatísticas* keep the tab bar on one line, *Por aprovar* keeps
status pills and the filter bar compact, the inbox summary avoids the
ordinal *1.ª* because Urbanist has no superscript *ª*, and *Por marca* (next to
*Por rede*) keeps the brand card's title on one line beside its toggle. On phones,
a More-sheet tile whose label can't fit beside its count (*Aprovações*) moves the
count onto the icon's corner; English keeps the reference layout.

## Locale-aware behaviour beyond strings

- **Search** in the inbox ignores case and accents (`marquez` finds *Márquez*),
  and highlights the match in the original spelling.
- **Tags** are transliterated instead of losing letters: *Devolução urgente* →
  `#devolucao-urgente`.
- Page titles keep their spaces in the letter-by-letter animation
  (*Boa tarde,* / *Calendário de*).

## Adding a language

1. Copy `src/i18n/pt-PT.tsx` to e.g. `src/i18n/es.tsx`, translate it, and type it
   `export const es: Messages = {…}` — the compiler lists anything missing.
2. Register it in `src/i18n/index.tsx`: the `Locale` union, `LOCALES` (named in
   its own language) and `CATALOGUES`, and map its tags in `matchLocale`.
3. Check the narrow places listed above at 1440 px and 390 px.

## Verification

- **Analytics**: the page, a network filter, the other metrics and rankings, the
  heatmap tooltip, the report dialog and the phone layout + More sheet were scanned
  the same way: no English left, no overflow, no horizontal scroll at 1440 or 390 px.
- **English unchanged**: the visible text plus every `aria-label`, `title` and
  `placeholder` of 13 states (overview, calendar week/month/list and drawer,
  inbox, filters, more menu, saved replies, contact panel, tag popover,
  placeholder route, mobile inbox) was dumped before the change and after it:
  **0 differences**, same document titles, `lang="en"`.
- **Portuguese complete**: the same states plus the account menu and mobile
  overview, thread and calendar were scanned for any English interface string
  (only workspace content remains English) and for text overflowing its box;
  no horizontal page scroll at 1440 or 390 px.
- **Switching**: menu → instant switch, saved across reloads, `?lang=` wins and
  is removed after a manual choice, `pt-BR` browsers get pt-PT, `fr-FR` gets English.
